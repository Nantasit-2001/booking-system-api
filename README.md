# ⚙️ Hotel Booking System (Backend)

This backend server supports the hotel booking platform [frontend](XXX!!!), handling API routes, authentication, database operations, vector-based AI chatbot, QR code payment, and room booking logic.  
It is maintained in a separate Git repository to ensure clean separation of concerns, better modularity, and scalable development.

---

## 📌 Overview

- Provides RESTful APIs consumed by the frontend for:
  - Hotel room filtering and availability checks
  - Room booking with conflict prevention
  - QR code deposit payment via Omise
  - Admin operations for room and hotel info management
  - AI chatbot responses powered by RAG
- Implements secure user authentication using **Clerk**
- Embeddings are generated using **Xenova (transformers.js)** on the server, stored in **PostgreSQL** (vector-compatible), and used to retrieve relevant hotel data
- Responses are generated by **Google Gemini 1.5 Flash**, given both the question and retrieved context
- Includes logic for blocking rooms during booking to prevent duplicate reservations

## 🤖 AI Chatbot Logic (RAG System)

The backend powers a 24/7 AI chatbot using a **Retrieval-Augmented Generation (RAG)** approach. This system intelligently answers user questions by dynamically retrieving and combining multiple sources of hotel-related data. The process is as follows:

1. **User submits a question** through the frontend → the backend API receives the input.
2. The first AI model (**Google Gemini 1.5 Flash**) analyzes the question to determine **what types of data** are needed to answer it, such as:
   - The user's **booking history**
   - Room availability for a specific date
   - Hotel-related information (fetched via **vector search**)
3. Based on the analysis, the backend performs corresponding queries:
   - If booking data is needed, it queries the relational **PostgreSQL** tables (e.g., reservations).
   - If hotel information is needed, the system takes the **key topic or intent** from the question, generates embeddings using **Xenova (transformers.js)**, and performs a **vector similarity search** on the hotel knowledge base stored in PostgreSQL.
4. After all relevant data is retrieved, the system constructs a contextual prompt combining:
   - The original user question
   - Fetched booking or room data
   - Retrieved hotel content (if any)
5. This full context is passed to the second AI model (**Google Gemini 1.5 Flash**) to generate a natural-language response.
6. The final answer is returned to the frontend for display to the user.

Admins can manage the hotel knowledge base via the admin panel. When new hotel info is added or updated, it is re-embedded using **Xenova** and saved to the vector-compatible database, ensuring the chatbot always answers based on the most current data.

This two-step AI coordination ensures precise, context-aware answers tailored to both general hotel info and individual user data.

## 🚫 Booking Conflict Prevention Logic

To prevent multiple users from booking the same room at the same time, the backend uses a **temporary blocking mechanism**:

- When a user opens the booking page, a record is created in the `blocked_room` table with:
  - `room_id`
  - `user_id`
  - `check_in` (start_date)
  - `check_out` (end_date)
  - `created_at`
- Before allowing a booking, the system checks:
  - If the selected dates **overlap** with any blocked entry for that room
  - If the conflict **is older than 15 minutes**, it is ignored
  - If the conflict **belongs to the same user**, it is allowed
- When booking is successfully completed:
  - All `blocked_room` records belonging to that user are deleted

This logic ensures fairness and prevents double-booking during simultaneous sessions.

## 🔧 Technologies & Tools

- **Node.js (Fastify)** — high-performance web framework for API development  
- **PostgreSQL RDS(AWS)** — relational database, extended to support vector search
- **Prisma ORM** — type-safe database client
- **Xenova (transformers.js)** — server-side text embedding for RAG 
- **Google Gemini 1.5 Flash** — response generation for chatbot  
- **Clerk** — authentication and user management  
- **Omise API** — payment gateway for QR code deposit  
- **CORS** — enable secure frontend-backend communication

## 🛠️ Development & Deployment

- The backend is structured for cloud deployment and currently integrates with **AWS RDS** for database hosting.
- Environment variables are used to configure secrets, DB URLs, Clerk keys, and Omise API credentials.
- Vector data for chatbot is embedded via Xenova and managed alongside relational booking data.
